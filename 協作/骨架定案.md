# 骨架定案

## 2026-09-23｜專案獨立性

- 顯示名稱：莓好預約站。
- 預定 GitHub Repository 名稱：`meihau-booking`。
- 必須是完全獨立的新專案，不掛在其他既有專案或分支底下。
- 不再使用先前於 `my-first-project` 建立的 `meihau-booking-site` 空分支。
- 第一階段保持最小專案骨架；網站、預約、付款、行事曆與後台分階段加入。

## 2026-09-25｜UI v2 品牌與施工邊界

- UI v2 視覺基準為使用者提供之核准參考圖與部署素材包，不以舊首頁配色回退。
- 主色系鎖定奶油白背景、莓果紅重點色、深棕文字與綠色輔助；首頁 Hero 桌機／手機使用獨立正式 WebP。
- 公開首頁資訊架構鎖定：導覽、Hero、四大服務、品牌故事、方案摘要、預約流程、安心承諾、最終 CTA、頁尾。
- 會員、地址、訂單、管理員與 API 行為屬既有功能骨架；純 UI 施工不得擅改資料庫、Auth、金流、價格計算或後端合約。
- 付款狀態與服務狀態必須維持不同視覺語意，不得共用同一組狀態色造成誤判。

## 2026-10-05｜人力・合作・資源媒合模組（使用者定案）

- 首頁資訊架構解鎖「一塊」：新增「找服務／加入莓好」雙入口區塊（位置：方案摘要之後、預約流程之前）；頁尾同步加入口連結。其餘首頁區塊仍鎖定。
- 作品集／附件第一版只收網址，不開檔案上傳（Storage）。
- 註冊維持 Google 登入（首次登入＝註冊），不另建帳密註冊。
- 系統權限：既有 `developer` 即計畫書的 `super_admin`（程式值不改名），`admin` 不變；`staff` 待需要時再加。只有 developer 可設 admin（伺服器端驗證）。
- 系統權限（`members.role`）與平台合作角色（`member_roles`：member／provider／partner／resource_seeker）永遠分開存放。
- 招募／合作申請統一用新計畫命名 `recruitment_applications`（含職缺應徵與自由申請「加入莓好」兩種），舊草案 `provider_applications` 作廢。
- 不建立第二套會員系統：一律擴充 `booking.members`（主鍵 `user_id uuid`）。

## 2026-10-07｜蝦皮分潤輪播（使用者定案）

- 每一頁（index.html、member.html、admin.html）在頁尾之前加一個獨立區塊放「主題式橫式分潤輪播」；此為首頁資訊架構第二個解鎖區塊。
- 區塊背景 80% 透明；商品文字、分潤揭露、完整推薦池連結保持清楚可讀。
- 必須使用安裝包原始模組檔（`C:\Users\User\Documents\Codex\分潤系統\網站輪播模組\通用主題式橫式分潤輪播_完整安裝包_合規過濾版_20261006.zip`，SHA256 已核對），不得重寫核心模組；分享池 `https://collshp.com/sberrychang?view=storefront`。

## 2026-10-08｜莓好圈命名與用途（使用者定案）

- 「預約莓好圈」＝網站首頁導覽與平台整體探索／媒合入口（人找人、服務找人、需求找人、合作媒合）。
- 「我的莓好圈」＝會員後台自己的編輯頁，以及每位會員唯一的公開分享頁。
- 會員後台與公開分享頁不得回退稱「我的媒合頁」；平台入口不得回退稱「社交媒合」。
- 後台與會員頁返回首頁的按鈕統一使用「回到莓好預約站」。
- 技術路徑暫保留 `match.html?profile=<slug>`；未來若有 rewrite hosting，再另案導入 `/circle/<slug>`，不得破壞既有分享連結。

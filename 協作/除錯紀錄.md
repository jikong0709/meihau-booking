# 除錯紀錄

## 2026-09-23｜Git 誤解析至父層

- 現象：在空的 `莓好預約站` 目錄執行 Git 狀態，顯示父層 `New project 2` 的未追蹤內容。
- 根因證據：目前目錄起初沒有自己的 `.git`，Git 向上找到父層倉庫。
- 處理：在目前資料夾建立獨立 Git Repository，避免後續誤改父層專案。
- 注意：不可在父層執行加入、提交或清理本專案檔案。

## 2026-09-24｜登入按鈕只進會員頁，未啟動帳號登入

- 現象：公開站的登入連結原先只有前端 Demo 跳頁，沒有 OAuth 與登入狀態檢查。
- 根因證據：正式版未配置 Google OAuth Client、Supabase Auth provider 與 runtime client；會員頁只有 Demo 資料。
- 處理：建立 Google OAuth Web Client、配置 Supabase Google provider／正式 redirect URL，前端改呼叫 `signInWithOAuth`，會員頁加入 session guard。
- 驗證：正式站點擊登入抵達 Google 選擇帳戶頁；未登入直開會員頁會返回首頁並附 `login=required`。

## 2026-09-25｜UI v2 手機版水平溢位與底部操作列過高

- 現象一：管理後台 390px 視窗出現約 4px 頁面水平溢位。
- 根因證據：月曆區塊的手機負 margin 讓外層寬度超出 viewport；不是月曆內部水平捲動本身。
- 解法：移除造成外層溢位的 margin，保留月曆容器內部可控的水平捲動；重測 `document.scrollingElement.scrollWidth === 390`。
- 現象二：會員中心手機版固定結帳列受舊的一欄 grid 規則影響，高度過大。
- 根因證據：390px 實測結帳列按鈕與摘要被排成單欄，壓縮主要內容空間。
- 解法：手機版結帳列維持兩欄排列並縮減間距；重測高度約 80px，完整落在 844px viewport 內。
- ⚠️地雷：響應式驗收必須同時檢查頁面外層 `scrollWidth` 與元件內部可捲動區，不能只看畫面是否出現捲軸。

## 2026-09-30｜Supabase 共用專案 migration history 不完整

- 現象：`supabase db push --dry-run` 列出多筆遠端既有 migration，但目前 Repository 沒有對應的本地檔案，因此標準 push 無法安全前進。
- 根因證據：CLI 的 local／remote migration list 顯示共用專案已有其他系統版本，不能假設本 Repository 擁有完整歷史。
- 禁止修法：不得為了讓 push 通過而批次 repair、回寫或偽造不屬於本專案的舊 migration。
- 解法：先以 transaction `BEGIN ... ROLLBACK` 執行完整 SQL 驗證且確認未留表，再以 `supabase db query --linked --file` 套用含 `BEGIN/COMMIT` 的單一 migration，最後只登記本次版本 `20260930055848`。
- 驗證：服務／選項／加購／詢價資料表與 RLS 已讀回；既有會員與訂單相關筆數未改變；schema lint 無錯誤。

## 2026-09-30｜Google OAuth 驗收受客戶帳號紅線限制

- 現象：公開頁與登入入口可驗證，但點擊正式站 Google 登入會開始客戶帳號操作。
- 處理：依最高規則停止於 OAuth 前，不以自動化代選帳號、不要求或記錄憑證。
- 目前證據：未登入開啟會員頁／管理頁皆正確導回首頁並附 `login=required`。
- 最小解鎖：由使用者親自登入，或另行明確授權客戶帳號操作，再執行會員／管理員完整驗收。

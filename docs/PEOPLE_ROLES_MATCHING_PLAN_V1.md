# 人員身分管理＋招募媒合｜規格草案 V1（暫停：等使用者提供完整資訊）

使用者 2026-10-05 已確認：只有 developer 可以把人設成 admin。其餘內容待使用者補完整資訊後再定案，尚未施工。

目標：後台可替每個帳號設定「備註、身分、是哪類服務的顧客、提供哪些服務」，並在網站公開招募資訊，作為未來服務媒合的地基。沿用陪工作 V1 已建立的 `providers`／`service_providers` 表，不重做。

## 1. 一個帳號可以同時有多種身分

| 身分 | 說明 | 存放 |
|---|---|---|
| 權限角色 | developer／admin／member（既有，管後台權限） | `members.role`＋`role_assignments` |
| 顧客標籤 | 這個人是哪些服務類別的顧客（錄音、AI、人力、陪工作…） | 新增 `member_customer_categories` |
| 服務提供者 | 這個人提供哪些服務（陪工作、錄音師、設計師…） | 既有 `providers` 加 `user_id` 連到會員；`service_providers` 綁服務 |
| 內部備註 | 例：「小雨」「開發者備用帳號」，只有後台看得到 | `members.admin_note` |

## 2. 後台新增「人員管理」工作區

- 會員列表：名稱、Email、權限角色、備註、顧客標籤、是否為服務提供者；可搜尋、篩選。
- 單人編輯：
  - 改備註、顧客標籤。
  - 開啟「服務提供者」→ 選擇提供哪些服務、對外顯示名稱、簡介、狀態（審核中／啟用／暫停）。
  - 改權限角色：**只有 developer 可以把人設成 admin**；admin 不能改別人的權限角色。
- 「招募管理」：新增／編輯招募職缺（標題、服務類型、工作內容、條件、報酬說明、狀態）。
- 「應徵審核」：查看應徵者，審核通過後一鍵轉成服務提供者。

## 3. 網站招募（媒合地基）

- 新頁面 `recruit.html`「加入莓好服務夥伴」，列出開放中的招募職缺（首頁資訊架構已鎖定，不新增首頁區塊，只在頁尾加連結）。
- 會員登入後可應徵：選職缺、自我介紹、可提供時段、作品連結。
- 應徵資料寫入 `provider_applications`，狀態：待審核／已通過／未錄取。
- 首批職缺建議：陪工作陪伴者、活動工作人員、錄音／後製、AI／設計接案。

## 4. 階段

- **P0（下一輪）**：備註、顧客標籤、服務提供者設定、人員管理工作區、權限分級。
- **P1**：招募頁＋應徵＋審核轉服務提供者。
- **P2**：顧客預約時可選服務提供者、服務者個人頁、排班、評價（即陪工作計畫書 P1／P2 的媒合部分）。

## 5. 安全與紅線

- 所有寫入走 `booking-api` 後台 API，伺服器端驗證 admin／developer。
- 應徵資料屬個人資料：只有本人與後台可讀。
- 不涉及金流；報酬說明僅文字，不做付款或分潤。
